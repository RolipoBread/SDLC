# Спецификация требований к программному обеспечению (SRS)
## Проект: BarterHub

### 1. Введение
**1.1 Назначение документа**
Настоящий документ описывает бизнес-требования и спецификацию программного обеспечения для веб-приложения «BarterHub» — платформы для обмена товарами без денег (бартера).

**1.2 Область применения**
Документ предназначен для команды разработки (Java + React), тестировщиков и заказчика. Служит основой для проектирования архитектуры и написания кода.

### 2. Общее описание
**2.1 Бизнес-цели**
Создать удобную площадку, где пользователи могут обменивать ненужные вещи на нужные без использования денег, с прозрачной системой статусов предложений и безопасным обменом контактами.

**2.2 Ключевые функции (MVP)**
- Регистрация и авторизация пользователей (с указанием номера телефона).
- Размещение объявлений (фото, описание, желаемый товар для обмена).
- Поиск и фильтрация объявлений.
- Механика «Офферов» (предложение обмена).
- Личный кабинет с двумя вкладками («Мои объявления» и «Мои предложения»).
- Система статусов офферов («На рассмотрении», «Отказано», «Торг», «Согласен»).
- Раскрытие контактов (номеров телефонов) после подтверждения сделки.

**2.3 Ограничения**
- Нет денежных расчетов (только бартер).
- Нет встроенного чата (связь только по телефону после согласия).
- Нет доставки (обмен происходит при личной встрече).

### 3. Функциональные требования
**REQ-AUTH-001:** Система должна предоставлять возможность регистрации с указанием имени, email и номера телефона.
**REQ-AUTH-002:** Номер телефона пользователя должен быть скрыт от других пользователей до момента подтверждения сделки.

**REQ-ITEM-001:** Пользователь должен иметь возможность создать объявление с загрузкой фотографии, описанием, категорией и указанием желаемого товара для обмена.
**REQ-ITEM-002:** Система должна отображать ленту объявлений с возможностью поиска и фильтрации по категориям и городу.

**REQ-OFFER-001:** Пользователь должен иметь возможность предложить обмен (создать оффер) на чужое объявление, указав описание своего товара и прикрепив фото.
**REQ-OFFER-002:** Автор исходного объявления должен видеть список всех поступивших офферов.
**REQ-OFFER-003:** Автор объявления должен иметь возможность изменить статус оффера на «Отказано», «Торг» или «Согласен».
**REQ-OFFER-004:** При статусе «Торг» предлагающий пользователь должен иметь возможность отредактировать свой оффер (добавить товар/условия).
**REQ-OFFER-005:** При статусе «Согласен» система должна раскрыть номера телефонов обеих сторон сделки.

### 4. Нефункциональные требования
**REQ-PERF-001:** Время загрузки главной страницы не должно превышать 2 секунд.
**REQ-SEC-001:** Пароли пользователей должны храниться в хешированном виде (BCrypt).
**REQ-UI-001:** Интерфейс должен быть адаптивным и корректно отображаться на мобильных устройствах и ПК.
