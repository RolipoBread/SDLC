# ADR-001: Использование Java (Spring Boot) для Backend

## Status
Accepted (Принято)

## Context
Для реализации серверной части платформы BarterHub необходимо выбрать язык программирования и фреймворк. Основные требования к бэкенду: высокая безопасность (работа с персональными данными и номерами телефонов), надежность, удобная работа с реляционной базой данных (PostgreSQL) и наличие зрелой экосистемы для быстрой разработки.

Рассматривались альтернативы:
*   **Node.js (Express/NestJS):** Быстрый старт, но менее строгая типизация и потенциальные проблемы с безопасностью при работе с транзакциями.
*   **Python (Django/FastAPI):** Хорош для прототипирования, но может уступать в производительности при высоких нагрузках и требует дополнительных усилий для строгой типизации.
*   **Java (Spring Boot):** Зрелый, строго типизированный язык с мощной экосистемой для enterprise-разработки.

## Decision
Мы выбираем **Java 17+ с фреймворком Spring Boot** для реализации Backend-части приложения.

## Consequences
**Положительные:**
*   **Безопасность:** Spring Security предоставляет готовые механизмы для аутентификации (JWT) и авторизации, что критически важно для защиты данных пользователей.
*   **Надежность:** Строгая типизация и проверка на этапе компиляции снижают количество ошибок в runtime.
*   **Работа с БД:** Spring Data JPA / JDBC обеспечивает удобную и производительную интеграцию с PostgreSQL.
*   **Экосистема:** Огромное количество готовых библиотек и большое сообщество разработчиков.

**Отрицательные (риски):**
*   **Скорость разработки:** Java требует больше boilerplate-кода по сравнению с Node.js или Python, что может замедлить разработку MVP. (Митигация: использование Spring Boot starters и Lombok для сокращения кода).
*   **Потребление памяти:** JVM требует больше оперативной памяти, чем Node.js. (Митигация: настройка параметров JVM и использование облегченных контейнеров Docker).
